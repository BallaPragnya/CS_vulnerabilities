ℹ️ What is This Page?

This page simulates an attacker-controlled website hosted on a different origin. In a real CSRF attack, the victim visits a page like this (hosted on evil.com) while being logged in to CampusConnect. The page automatically submits a hidden form to the CampusConnect server. Because the browser sends the session cookie automatically, the server processes the forged request.

Prerequisite: You must be logged in to CampusConnect at localhost:3000 in another tab.
1
Victim logs in to CampusConnect at localhost:3000. Browser stores session cookie.
2
Attacker tricks victim into visiting this page (e.g. via email link, social media).
3
This page auto-submits a hidden form to localhost:3000/api/settings/email-vuln.
4
Browser includes victim's session cookie. Server accepts the forged request!
5
Victim's email is changed to hacker@evil.com without their knowledge.

⚠️ Attack 1: Vulnerable Endpoint (No CSRF Protection)

Sends a forged POST to /api/settings/email-vuln which has no CSRF token validation. If you are logged in, the request will succeed.

✅ Attack 2: Secure Endpoint (CSRF Token Required)

Sends the same forged POST to /api/settings/email-safe which requires a valid CSRF token. The attacker cannot read the token (Same-Origin Policy) so the forged request will be rejected.
