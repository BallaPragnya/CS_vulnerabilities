💉 Module 5 – CSRF: Cross-Site Request Forgery

CSRF exploits the fact that browsers automatically include session cookies with every request, even those triggered by a page on a different origin.

An attacker can host a page with a hidden, auto-submitting HTML form that sends a POST request to our application. If the user is logged in, the browser attaches their session cookie and the server processes the request — without the user knowing.

Attacker's page (auto-submitting form):
<form action="http://localhost:3000/api/settings/email-vuln" method="POST">
  <input name="email" value="hacker@evil.com" />
</form>
<script>document.forms[0].submit();</script>
⚠️ VULNERABLE MODE – No CSRF token. Any forged request is accepted.
✅ SECURE MODE – CSRF token validated. Forged requests are rejected.
👤 Victim's Form (Legitimate Request)

This is the normal form the victim uses to update their email. In secure mode it fetches a CSRF token first.
